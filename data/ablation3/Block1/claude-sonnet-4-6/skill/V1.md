## Repair Strategy Overview

All accepted repair trials on layer V1 affected only the X direction. No Y-direction moves or resizes appear in any accepted record. Both accepted trials touched M1, M2, and V1 simultaneously, reflecting that V1 geometry is fully determined by its parent instance placement and the M2 wires that connect to it (trial:i03.ug.whole_design.00, trial:i05.ug.whole_design.00).

## Instance-Move Repairs (V1.W.1, V1.S.1, V1.S.2, V1.S.3, V1.S.4, V1.AUX.1, V1.M1.EN.1)

Moving a cell instance that contains a V1 shifts the via in all layers simultaneously and is the primary accepted repair action. Accepted X-direction displacements range from ±36 DBU to ±72 DBU (trial:i03.ug.whole_design.00, trial:i05.ug.whole_design.00). The majority of moves in both trials are positive (rightward), with a small number of negative (leftward) moves used to resolve violations on instances whose neighbors were moved away (trial:i03.ug.whole_design.00: two instances moved −64 DBU; trial:i05.ug.whole_design.00: two instances moved −72 DBU, one moved −64 DBU). This bidirectional pattern indicates that a congested cluster requires simultaneous rightward and leftward spreading to satisfy minimum spacing rules, rather than moving all instances in a single direction.

All 32 move_instance operations in trial:i03.ug.whole_design.00 used a uniform delta of exactly ±64 DBU. In trial:i05.ug.whole_design.00, positive move magnitudes were non-uniform (36, 44, or 48 DBU per instance), with the 44-DBU instances always paired with a resize_end on an M2 polygon (see below). Do not apply a single uniform delta when instances in the same cluster have differing M2 end-cap geometries; use per-instance deltas matched to each instance's M2 situation (trial:i05.ug.whole_design.00).

## M2 End-Cap Extension Paired with Instance Move (V1.M2.EN.2, V1.M2.AUX.2)

When an instance is moved +44 DBU in X, the M2 polygon whose high-X end connects to that instance must be extended by the same +44 DBU at its high end (resize_end, axis x, end high). This pattern appears for five instance/polygon pairs in trial:i05.ug.whole_design.00: (i0060, p1255), (i0188, p1270), (i0294, p1295), (i0485, p1309), (i0507, p1320). Instances moved by 36 DBU or 48 DBU in the same trial do not have a paired resize_end, indicating those moves did not displace the V1 relative to the existing M2 end-cap boundary. Always apply a resize_end to the M2 polygon end-cap when the instance move would otherwise leave the V1 partially or fully outside the M2 boundary (V1.M2.EN.2) or misalign the V1 width relative to M2 (V1.M2.AUX.2), and match the resize delta exactly to the move delta (trial:i05.ug.whole_design.00).

The V1.M2.AUX.2 rule requires V1 to be exactly the same width as M2 along the direction perpendicular to the M2 length. Because instance moves carry V1 without resizing it, the M2 polygon width perpendicular to its length must already be correct before the move; resize_end operations in the accepted trials touch only the along-length end of M2, not the perpendicular edges (trial:i05.ug.whole_design.00).

V1.AUX.1 requires every V1 polygon to be inside both M1 and M2. When extending M2 less than the instance move delta, or not extending M2 at all for a 44-DBU move, V1 would exit M2; the accepted pattern always pairs the 44-DBU instance move with a 44-DBU M2 end-cap extension (trial:i05.ug.whole_design.00).
