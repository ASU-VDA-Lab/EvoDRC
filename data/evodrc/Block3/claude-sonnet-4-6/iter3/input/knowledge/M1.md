## Per-rule recipes

### Family A: M1-via cluster (V0.M1.AUX.3, M1.S.2, M1.S.6, V1.M1.EN.1)

These four rules cluster around via instances placed where local M1 geometry fails width-matching, spacing, or enclosure constraints. A single site fires one to three of them, not necessarily all four; in the reference design 18 of 37 violations belong to this family, and 3 of 12 VIA12 moves cleared violations from 2-3 distinct rules in a single operation (seed, reference-design-verified).

Rule semantics (ASAP7 rule deck):
- V0.M1.AUX.3: The rule checks V0 edges not co-incident with M1 edges; it flags any V0 whose convex non-coincident horizontal and vertical edges interact, indicating the V0 width perpendicular to M1 length does not equal the M1 width at that location (seed, reference-design-verified).
- V1.M1.EN.1 (deck hgood/vgood construction; description "5 & 2 nm"): on ONE pair of opposite sides -- either the x-pair or the y-pair -- both sides are checked for >= 2 nm (8 dbu) AND at least one of the two >= 5 nm (20 dbu). The rule fires when NEITHER pair achieves this on the merged M1 (seed, reference-design-verified).
- M1.S.2: Tip-to-side spacing >= 25 nm (100 dbu) when one edge is <= 36 nm and the other > 36 nm (seed, reference-design-verified).
- M1.S.6: Corner-to-corner spacing >= 20 nm (80 dbu) (seed, reference-design-verified).

Root cause pattern: A via instance (VIA_VIA12 or similar) sits at a coordinate where the merged M1 has an edge mismatch or insufficient extension. Moving the via instance to a nearby M1-valid position -- with or without extending the associated top-level M2 polygon -- clears one or more rules of this family at once (seed, reference-design-verified; trial:i01.ug.leaf_0009.07; trial:i01.ug.Block3_union_row2.01).

Recipe -- via-and-pad slide:

Step 1. For each violation in this family, locate the via instance whose bounding box overlaps or abuts the violation bbox (seed, reference-design-verified).

Step 2. Determine the required lateral delta. The new via position places the V0 y-extent coincident with the M1 y-extent at the landing point (seed, reference-design-verified). For V1.M1.EN.1 the merged M1 at the new position must satisfy the hgood or vgood condition on ONE pair of opposite sides (seed, reference-design-verified). Repositioning the via away from nearby metal also clears M1.S.2 and M1.S.6 by removing the tip/corner proximity to the neighbor (seed, reference-design-verified; trial:i01.ug.Block3_union_row1.00).

Step 3. Apply the delta to the via instance. Negative x deltas are valid (trial:i01.ug.leaf_0013.09: delta [-36,0] dbu, conn_preserved=true, zero new violations; trial:i02.ug.leaf_0001.00: delta [-36,0] dbu, conn_preserved=true, zero new violations). Confirmed correct x moves from iterations 1-2: 36 dbu (trial:i01.ug.leaf_0009.07; trial:i01.ug.leaf_0006.04; trial:i01.ug.Block3_union_row2.01; trial:i01.ug.Block3_union_row5.02), 72 dbu (trial:i01.ug.leaf_0012.08; trial:i01.ug.Block3_union_row8.03), 104 dbu (trial:i02.ug.leaf_0002.01), 108 dbu (trial:i01.ug.Block3_union_row8.03), 136 dbu (trial:i01.ug.Block3_union_row1.00). A 4 dbu x move alongside a 20 dbu y resize_end on a top-level polygon is confirmed correct in a fix that also touches M3 (trial:i01.ug.leaf_0008.06).

Step 4. When multiple vias are fixed in the same locus, their deltas need not be identical; use the delta that satisfies the constraint at each via's specific location (trial:i01.ug.Block3_union_row8.03: four via moves in the same locus at 108, 108, 72, 72 dbu; trial:i01.ug.Block3_union_row1.00: three via moves in the same locus all at 136 dbu).

Step 5. For each moved via, check whether the associated top-level M2 (layer 20) polygon requires extension to maintain landing coverage. When the via moves into a position already covered by existing metal, no polygon edit is needed (trial:i01.ug.Block3_union_row2.01; trial:i01.ug.leaf_0006.04; trial:i01.ug.leaf_0009.07; trial:i01.ug.leaf_0013.09; trial:i02.ug.leaf_0001.00). When a top-level M2 polygon requires extension, resize the high end on the axis of via motion by a delta >= the via move delta; the extension delta exceeds the via delta when the landing pad's trailing coverage would otherwise be lost (trial:i01.ug.Block3_union_row1.00: via +136 dbu, polygon +192 dbu; trial:i01.ug.leaf_0007.05: via +36 dbu, polygon +56 dbu; trial:i01.ug.leaf_0012.08: via +72 dbu, polygon +108 dbu; trial:i01.ug.Block3_union_row8.03: via +108 dbu, polygon +164 dbu; via +72 dbu, polygons +128 and +92 dbu; trial:i02.ug.leaf_0002.01: via +104 dbu, polygon +128 dbu). Extend the high end only; do not translate the polygon (seed, reference-design-verified; trial:i01.ug.Block3_union_row5.02: a via +36 dbu move paired with a resize_end +36 dbu on the high-x end, not a polygon translate).

Step 6. If a stacked VIA23 is co-located with the moved VIA12, decide per level whether to co-move or anchor, using the pre-move question: does the V2 level at the OLD position still need VIA23 there to reach M3, and does VIA23's own alignment remain legal at the old coordinate?
  (a) Co-move case: move VIA23 by the same delta when the M2 landing must travel with the V1 fix (seed, reference-design-verified).
  (b) Anchor case: leave VIA23 at the original coordinate when M2-M3 alignment stays correct at the old position (seed, reference-design-verified).
  (c) Partial case: VIA12 and VIA23 take different per-axis deltas when each level requires a different adjustment (seed, reference-design-verified).
  After any VIA23 move, extend the relevant M2 or M3 polygon to cover the via at its new position if coverage is lost (seed, reference-design-verified; trial:i01.ug.leaf_0008.06: fix includes a y-axis resize_end +20 dbu on a top-level polygon alongside x-axis via moves, touching M1, M2, M3, and V1).

Enclosure is checked on merged metal; the final DRC-clean state follows from the merged geometry at the new position, not from any single polygon boundary alone (seed, reference-design-verified).

Connectivity preservation: all 12 repairs across iterations 1-2 achieved conn_preserved=true with zero new violations inside or outside the crop window, confirming the recipe is safe for Block3 geometries (trial:i01.ug.Block3_union_row1.00; trial:i01.ug.Block3_union_row2.01; trial:i01.ug.Block3_union_row5.02; trial:i01.ug.Block3_union_row8.03; trial:i01.ug.leaf_0006.04; trial:i01.ug.leaf_0007.05; trial:i01.ug.leaf_0008.06; trial:i01.ug.leaf_0009.07; trial:i01.ug.leaf_0012.08; trial:i01.ug.leaf_0013.09; trial:i02.ug.leaf_0001.00; trial:i02.ug.leaf_0002.01).

## Final-pair measured facts

- Moving via instances without touching cell definitions is sufficient to clear V0.M1.AUX.3, V1.M1.EN.1, M1.S.2, and M1.S.6, provided metal polygons are co-moved or extended to maintain coverage (seed, reference-design-verified).
