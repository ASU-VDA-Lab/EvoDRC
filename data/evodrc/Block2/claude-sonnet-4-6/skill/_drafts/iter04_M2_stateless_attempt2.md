## M2 Repair Strategy: Instance Moves and Connectivity Preservation

All accepted repairs in this history preserve connectivity (conn_preserved:true in every trial: trial:i01.ug.Block2_union_row1.00, trial:i01.ug.Block2_union_row3.01, trial:i01.ug.Block2_union_row5.02, trial:i01.ug.leaf_0001.03, trial:i01.ug.leaf_0004.04, trial:i01.ug.leaf_0007.05, trial:i01.ug.leaf_0011.06, trial:i04.ug.leaf_0002.01). Do not apply any M2 repair that breaks connectivity; the gating mechanism rejects all ops that do not preserve connectivity. Trial:i04.ug.leaf_0002.01 demonstrates that even when a repair introduces one new in-crop violation (n_new_in_crop:1), it is still accepted as gated_in because connectivity is preserved.

## Move Deltas and Grid Alignment

The unit_gate channel moves instances in multiples of 36 dbu along the x-axis. Single-instance moves of 36 dbu in x were sufficient to clear violations without any polygon resize in trial:i01.ug.Block2_union_row1.00 (two instances each moved [36,0]), trial:i01.ug.leaf_0004.04 (one instance moved [36,0]), and trial:i01.ug.leaf_0007.05 (one instance moved [36,0]). Larger violations required larger displacements: 64 dbu in trial:i01.ug.Block2_union_row5.02 (three instances moved [64,0]) and 128 dbu instance move in trial:i01.ug.leaf_0001.03. Negative x-direction moves (-64 dbu) are also valid, as in trial:i04.ug.leaf_0002.01. Use the smallest delta that clears the violation, respecting 36 dbu grid increments.

## Polygon Resize Must Accompany Instance Moves When M2 Endpoints Are Affected

When a set of instance moves shifts M2 polygon endpoints relative to adjacent polygons or via stacks, the repair must include matching resize_end operations on the affected M2 polygons in the same op bundle. In trial:i01.ug.Block2_union_row3.01, two instances were moved [36,0] and polygon p1040 received a resize_end on axis:x end:high by the same 36 dbu delta. In trial:i01.ug.Block2_union_row5.02, three instances moved [64,0] and polygons p1059 and p1057 each received resize_end on axis:x end:high by 64 dbu. In trial:i01.ug.leaf_0011.06, one instance moved [36,0] and polygon p1052 received resize_end on axis:x end:high by 36 dbu. In trial:i01.ug.leaf_0001.03, one instance moved [128,0] while polygon p1065 received resize_end axis:x end:high by 184 dbu and polygon p957 received resize_end axis:x end:low by 176 dbu, indicating that both the high and low ends of distinct M2 polygons needed separate adjustment to maintain valid enclosure and spacing. In trial:i04.ug.leaf_0002.01, polygon p937 was moved axis:x by -64 dbu and polygon p1036 was moved axis:y by 36 dbu as part of a mixed-direction repair. Match each resize_end delta to the corresponding instance move delta unless the polygon geometry requires a different adjustment to meet enclosure rules (as in trial:i01.ug.leaf_0001.03 where the instance moved 128 but polygons moved 184 and 176 respectively).

## Via Cell Repairs via cu_pool Channel: Shrink M2/M3 in Y

The cu_pool channel repairs violations associated with the via cell VIA_VIA23_1_3_36_36 by shrinking M2 (and M3) polygons in the y-axis. In trial:i01.cu.def:VIA_VIA23_1_3_36_36.00, four M2 polygons (p965, p964, p963, p962) were each shrunk by -64 dbu in y, and the via cell shape was resized by -40 dbu in y; this reduced the violation count by 8 (delta_total:-8). The same recipe was applied in trial:i02.cu.def:VIA_VIA23_1_3_36_36.00 targeting polygons p961, p960, p959, p958 with identical deltas, again yielding delta_total:-8. Apply a -64 dbu y-shrink to each affected M2 polygon in the via cell group, paired with a -40 dbu resize of the via shape itself, to resolve violations associated with VIA_VIA23_1_3_36_36.

## Multi-Layer Repair Scope

M2 repairs consistently co-touch M1 and V1 (trial:i01.ug.Block2_union_row1.00, trial:i01.ug.Block2_union_row3.01, trial:i01.ug.Block2_union_row5.02, trial:i01.ug.leaf_0004.04, trial:i01.ug.leaf_0007.05, trial:i01.ug.leaf_0011.06). When the unit also contains higher-level routing, M4 and M5 are co-touched: trial:i01.ug.leaf_0001.03 touched M1, M2, M4, V1; trial:i04.ug.leaf_0002.01 touched M1, M2, M4, M5, V1, V4. Via cell repairs (cu_pool) co-touch M2, M3, and V2 (trial:i01.cu.def:VIA_VIA23_1_3_36_36.00, trial:i02.cu.def:VIA_VIA23_1_3_36_36.00). Scope each repair operation to include all layers that move with the instance or via group; isolated M2 polygon edits without matching moves on co-located layers will violate enclosure rules V1.M2.EN.2 and V1.M2.AUX.2.

## V2.M2.EN.1 and V1.M2.AUX.2 Enclosure Constraints Drive Resize Asymmetry

V1.M2.AUX.2 requires V1 width to exactly match M2 width in the perpendicular direction, and V1.M2.EN.2 requires M2 to enclose V1 by 5 nm on two opposite sides. When an instance move shifts M2 by a given delta, polygon resize_end magnitudes must re-establish valid enclosure on both the moved end and the stationary end. In trial:i01.ug.leaf_0001.03 the instance moved 128 dbu while the polygon high-end was extended 184 dbu and a second polygon's low-end was extended 176 dbu, showing that resize magnitudes are not always equal to instance move magnitudes—they are determined by the enclosure gap to close. Do not assume resize_end delta equals move_instance delta; calculate the required enclosure and apply the exact delta needed.

## Direction of Moves: X-Axis Dominates; Y-Axis Used for Orthogonal Correction

The overwhelming majority of unit_gate repairs move instances along the x-axis only (trial:i01.ug.Block2_union_row1.00, trial:i01.ug.Block2_union_row3.01, trial:i01.ug.Block2_union_row5.02, trial:i01.ug.leaf_0001.03, trial:i01.ug.leaf_0004.04, trial:i01.ug.leaf_0007.05, trial:i01.ug.leaf_0011.06). In trial:i04.ug.leaf_0002.01, a compound repair moved four instances in x (-64 dbu) while one instance (i0063) moved in y (+36 dbu) and one polygon (p1036) moved in y (+36 dbu). This confirms y-axis moves are valid for M2 tip-spacing violations (M2.S.2, M2.S.3, M2.S.4, M2.S.5) when the violating edges are along the y-direction, but should be used only when x-axis adjustment alone cannot resolve the violation, as all single-axis x-only repairs accepted cleanly in iteration 1 (trial:i01.ug.Block2_union_row1.00 through trial:i01.ug.leaf_0011.06).
