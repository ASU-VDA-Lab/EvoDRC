## Geometry Constraints from Rule Structure

V1.W.1 sets a minimum V1 width of 18 nm along the M2 length direction. V1.M2.AUX.2 requires V1 width to equal M2 width perpendicular to M2 length, so the M2 track width also cannot fall below 18 nm in the perpendicular direction without triggering a V1.W.1 violation. V1.M2.EN.2 requires M2 to enclose V1 by at least 5 nm on two opposite sides, with the alternative being 5 nm on one side and 0 nm (flush) on the other. The flush-end case (0 nm enclosure) is only valid when the V1 edge is coincident with the M2 edge — the v1_wec / v1_nec classification axis in V1.S.1 through V1.S.4. The end-cap state of a via determines which spacing rule applies: an M2 end-cap of 5 nm (v1_nec) triggers stricter corner-to-corner spacing (V1.S.3: 30 nm euclidean minimum between two nec vias; V1.S.4: 27 nm between one nec and one wec via), while the flush-end case (v1_wec) allows a smaller corner spacing (V1.S.2: 23 nm euclidean via v1_wec_mask). The resize_end operations in all iterations extended M2 polygon ends, changing wec→nec classification or increasing existing end-caps (trial:i01.ug.Block6_union_row7.03, trial:i01.ug.Block6_union_row8.04, trial:i01.ug.leaf_0015.07, trial:i02.ug.Block6_union_row7.00, trial:i02.ug.leaf_0003.02, trial:i02.ug.leaf_0008.05, trial:i03.ug.leaf_0002.00).
