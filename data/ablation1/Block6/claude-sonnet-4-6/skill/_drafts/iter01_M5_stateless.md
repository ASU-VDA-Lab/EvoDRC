## M5 Grid and Routing Track Constraints (Rules Context)

M5.AUX.1 requires all M5 vertical edges to land on a 24 nm x-grid. M5.AUX.2 requires minimum-width M5 tracks to be centered on vertical routing tracks spaced at 192 dbu pitch with 48 dbu offset. M5.AUX.3 prohibits any bend (corner with angle in 0°–90°); M5 shapes must be purely rectilinear runs. M5.AUX.4 prohibits the outside edge of a wide M5 polygon from touching a routing track edge. No repair has yet been measured for these four rules in this layer's history; the only M5 shape operations recorded are the y-axis shrink in a VIA_VIA45 cell (trial:i01.cu.def:VIA_VIA45_1_2_58_58.00). Do not adjust M5 horizontal position or introduce corners when repairing V4.M5.AUX.2, as doing so would risk triggering M5.AUX.1, M5.AUX.2, M5.AUX.3, or M5.AUX.4.

## Width and Spacing Rule Boundaries

M5.W.1 sets the minimum horizontal width at 24 nm. M5.W.2 caps horizontal width at 480 nm. M5.W.3 and M5.W.4 together forbid horizontal widths that are even integer multiples of 24 nm (48, 96, 144, 192, 240, 288, 336, 384, 432, 480 nm) or that span an even number of minimum-width routing tracks (widths at 72, 168, 264, 360, 456 nm). M5.W.5 sets minimum vertical width at 44 nm. The y-axis M5 shrink of 88 dbu applied in trial:i01.cu.def:VIA_VIA45_1_2_58_58.00 reduced M5 vertical extent; verify the resulting vertical width remains at or above 44 nm (M5.W.5) after any y-axis resize on M5. No horizontal M5 width adjustment has been measured in this iteration's history; apply width rule checks before proposing any horizontal M5 resize.

## Spacing Rule Boundaries

M5.S.1 requires 24 nm minimum horizontal spacing between M5 polygons. M5.S.2 requires 40 nm minimum vertical spacing. M5.S.3 requires 40 nm tip-to-tip spacing between polygons on adjacent tracks that do not share parallel run length. M5.S.4 requires 40 nm tip-to-tip spacing between polygons on adjacent tracks that do share parallel run length. M5.S.5 requires a minimum parallel run length of 44 nm when two M5 polygons are on adjacent tracks. The M5 y-axis shrink in trial:i01.cu.def:VIA_VIA45_1_2_58_58.00 reduced total violations without triggering any of these spacing rules (connectivity preserved, net violation count fell). No spacing violations were generated by the V5 y-axis resize in trial:i01.cu.def:VIA_VIA56_2_2_66_58.02 either. When resizing M5 in y, confirm the resulting tip clearances do not violate M5.S.2, M5.S.3, or M5.S.4 against any neighboring M5 run on an adjacent track.
