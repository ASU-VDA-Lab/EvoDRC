## Geometry Constraints from Rule Structure

V1.W.1 sets a minimum V1 width of 18 nm along the M2 length direction. V1.M2.AUX.2 requires V1 width to equal M2 width perpendicular to M2 length, so the M2 track width also cannot fall below 18 nm in the perpendicular direction without triggering a V1.W.1 violation on the via. V1.M2.EN.2 requires M2 to enclose V1 by at least 5 nm on two opposite sides, with the alternative being 5 nm on one side and 0 nm (flush) on the other. The flush-end case (0 nm enclosure) is only valid when the V1 edge is coincident with the M2 edge, which is the v1_wec / v1_nec classification axis in V1.S.1 through V1.S.4. The end-cap state of a via therefore determines which spacing rule applies: an M2 end-cap of 5 nm (v1_nec) triggers stricter corner-to-corner spacing (V1.S.3: 30 nm euclidean minimum between two nec vias), while the flush-end case (v1_wec) allows a smaller corner spacing (V1.S.2: 23 nm euclidean via v1_wec_mask). The resize_end operations observed in this iteration (trial:i01.ug.Block6_union_row7.03, trial:i01.ug.Block6_union_row8.04, trial:i01.ug.leaf_0015.07) extended M2 polygon ends, which changes the via from v1_wec to v1_nec classification or increases an existing end-cap, affecting which spacing rule governs that via pair.
