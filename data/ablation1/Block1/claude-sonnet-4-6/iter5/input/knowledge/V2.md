## V2 Rule Structure and Measured Repair Behavior

**Rule topology.** V2 violations span four categories: width (V2.W.1), spacing (V2.S.1-V2.S.4), enclosure (V2.M2.EN.1, V2.M3.EN.2), and containment/alignment (V2.AUX.1, V2.M3.AUX.2). The spacing rules are conditioned on end-cap presence: whether a V2 instance is a "no-end-cap" (NEC) type whose entire edge set coincides with M3 edges, or a "with-end-cap" (WEC) type that has at least one non-coincident edge. The effective spacing thresholds differ by combination: same-track or aligned-track projection 18 nm (V2.S.1), parallel not-aligned 27 nm (V2.S.1), Euclidean WEC-WEC 23 nm (V2.S.2), Euclidean NEC-NEC 30 nm (V2.S.3), Euclidean WEC-NEC 27 nm (V2.S.4).

**Enclosure constraints couple M3 resize to V2 validity.** V2.M3.EN.2 requires M3 to enclose V2 on two opposite sides by either 5 & 5 nm or 5 & 0 nm (projection). V2.M3.AUX.2 additionally requires that V2 width perpendicular to the M3 length direction exactly match the M3 width in that direction. These two rules together mean that any change to M3 geometry directly constrains what V2 dimensions remain legal.

**V2.AUX.1 and V2.M3.AUX.2 impose hard geometric containment.** V2 must reside inside the intersection of M2 and M3 (V2.AUX.1). Any resize of M3 that reduces its extent risks pushing V2 outside M3, triggering V2.AUX.1. Separately, V2.M3.AUX.2 enforces exact width matching between V2 and M3 in the direction perpendicular to M3 length. A y-axis M3 shrink (as in trial:i02.cu.def:VIA_VIA23_1_3_36_36.00) directly risks a V2.M3.AUX.2 violation if V2 width in that axis no longer matches the modified M3 width; the zero-delta result in that trial confirms that the specific delta used did not trigger new violations but also resolved none. An x-axis instance move (trial:i04.ug.leaf_0002.01) translates all V2, M2, and M3 geometry together, preserving internal geometric relationships and avoiding V2.AUX.1 and V2.M3.AUX.2 violations due to unchanged relative positions within the moved cell.

**End-cap classification drives which spacing rules fire.** Because V2.S.1 through V2.S.4 use the WEC/NEC classification, any repair that changes M3 edge coincidence with V2 edges (e.g., extending or shrinking M3 so that previously coincident edges become non-coincident) changes the effective spacing rule and threshold that applies. A `move_instance` translation does not alter internal edge coincidence between V2 and M3 within the moved cell, so the end-cap classification of the moved instance remains unchanged (trial:i04.ug.leaf_0002.01). No measured trial demonstrates a repair that successfully shifts a V2 instance from one end-cap class to another with a net-positive DRC outcome.

**V2.M2.EN.1 is independent of M3 changes.** The M2 enclosure rule (minimum 5 nm on at least two opposite sides) is not affected by M3 resizing.
