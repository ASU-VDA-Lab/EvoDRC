## Via Enclosure and Chain-Fix Patterns

**Enclosure requirements for vias landing on M4.** Rule V3.M4.EN.2 requires M4 to enclose V3 by at least 11 nm on at least two opposite sides; rule V4.M4.EN.1 imposes the same 11 nm two-sided enclosure requirement for V4. In trial:i01.cu.def:VIA_VIA34_1_2_58_52.00, insufficient vertical enclosure was corrected by expanding the M4 shape in cell VIA_VIA45_1_2_58_58 by +88 dbu along the y-axis. That single M4 resize, coordinated with matching y-axis resizes on the co-located V4 shapes and a separate M3/V3 resize in cell VIA_VIA34_1_2_58_52, reduced the total violation count by 13 across the two affected windows (leaf_0009: 25→18, leaf_0010: 25→19) and preserved all connectivity (trial:i01.cu.def:VIA_VIA34_1_2_58_52.00).

**Chain-fix scope for via-cell enclosure repairs.** The M4 resize was applied as part of a six-operation group tagged `chain_fix`, touching layers M3, M4, M5, V3, and V4 within the same via-cell cluster. In trial:i01.cu.def:VIA_VIA34_1_2_58_52.00, the M4 shape (`shape_index 0`) in the upper via cell (VIA_VIA45_1_2_58_58) received the same +88 dbu delta as the V4 shapes in that cell, confirming that the via metal and its enclosing via shapes must be resized together. Resizing M4 alone without matching V4 adjustment—or vice versa—would leave the V4/M4 co-enclosure geometry inconsistent and risk introducing rule V3.M4.AUX.2 violations (which requires V3 to be exactly the same width as M4 in the direction perpendicular to M4's length).

## Vertical Width Rules and Forbidden Sizes

**Minimum and maximum vertical width.** Rule M4.W.1 sets the minimum vertical width of M4 at 24 nm; rule M4.W.2 sets the maximum at 480 nm. The +88 dbu vertical expansion applied in trial:i01.cu.cu.def:VIA_VIA34_1_2_58_52.00 produced a post-fix shape that remained within these bounds, confirming that enclosure-driven expansions of this magnitude are geometrically legal provided the starting width is not already near the 480 nm ceiling.

**Forbidden even-multiple widths (M4.W.3 and M4.W.4).** Rule M4.W.3 prohibits M4 vertical widths that are exact even-integer multiples of the 24 nm minimum: 48, 96, 144, 192, 240, 288, 336, 384, 432, and 480 nm are all forbidden. Rule M4.W.4 adds a second forbidden set corresponding to widths that span an even number of minimum-width routing tracks vertically: 72, 168, 264, 360, and 456 nm. When computing the post-resize vertical width after applying a y-axis delta, the resulting height must not fall on any value in either forbidden list. The repair executed in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 avoided these values, and the trial was applied without triggering M4.W.3 or M4.W.4 violations.

**Minimum horizontal width.** Rule M4.W.5 sets the minimum horizontal width of M4 at 44 nm. The trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 operation resized only along the y-axis, leaving horizontal extent unchanged; no M4.W.5 violation was introduced.

## Spacing and Track Adjacency Rules

**Vertical spacing.** Rule M4.S.1 requires a minimum vertical spacing of 24 nm between M4 polygon edges regardless of edge length or mask color. When expanding an M4 shape vertically to satisfy enclosure, the top or bottom edge moves toward adjacent M4 geometry; the post-expansion edge separation must remain ≥24 nm. The trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 expansion of +88 dbu was applied inside a via-cell context where adjacent M4 routing at the design boundary did not create a M4.S.1 violation, and the repair was accepted.

**Horizontal spacing and tip rules.** Rule M4.S.2 requires a minimum horizontal spacing of 40 nm between vertical M4 edges. Rules M4.S.3 and M4.S.4 each require a minimum tip-to-tip spacing of 40 nm on adjacent tracks (M4.S.3 for polygons without shared parallel run length; M4.S.4 for those that share parallel run length). Rule M4.S.5 sets a minimum parallel run length of 44 nm for M4 polygons on adjacent tracks. The y-axis-only resize in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 did not alter horizontal geometry, so these rules were not perturbed by the repair.

## Grid and Routing Track Placement

**Horizontal-edge grid (M4.AUX.1).** Rule M4.AUX.1 requires all M4 horizontal edges to lie on a 24 nm grid (1 dbu horizontal, 24 nm vertical grid). Any y-axis resize must produce a resulting edge coordinate that is a multiple of 24 nm. The +88 dbu delta applied in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 must have resulted in a grid-aligned final coordinate, as the repair was accepted without generating an M4.AUX.1 violation. When computing resize deltas for M4 enclosure fixes, constrain the delta to produce final edge positions that satisfy: y_final mod 24 == 0.

**Routing track centering for minimum-width shapes (M4.AUX.2).** Rule M4.AUX.2 requires minimum-width M4 tracks (those not wide enough to survive a ±13 nm y-erosion) to have their centerline on a grid with pitch 192 dbu and offset 48 dbu from the origin. Resizing a minimum-width M4 shape vertically must keep the centerline on this grid; the symmetric delta required to do so is a multiple of 192 dbu (to stay on the same track) or must deliberately move to the nearest valid track center. The chain fix in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 operated on a via-cell shape rather than a free routing segment, but the same grid constraint applies to any minimum-width M4 geometry the resize produces.

**No bending (M4.AUX.3).** Rule M4.AUX.3 prohibits any M4 polygon that contains a corner with an interior angle between 0° and 90° (exclusive), i.e., M4 must remain strictly rectilinear with no L-turns. Resize operations must not introduce new corner angles. The y-only resize in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00 preserved the rectangular shape of the M4 via-land, consistent with this rule.

**Wide M4 track-edge constraint (M4.AUX.4).** Rule M4.AUX.4 prohibits the outer horizontal edges of wide M4 polygons (those that survive a ±13 nm y-erosion) from coinciding with any horizontal routing-track edge derived from the minimum-width band positions. When expanding a near-minimum-width M4 shape into the wide category by adding a large y-delta, verify the resulting outer edges do not land exactly on a routing-track boundary. This constraint was not triggered in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00, which used an 88 dbu delta that kept the shape in via-land geometry rather than a wide routing polygon.

**Non-orthogonal geometry prohibition.** The blanket GEOMETRY.NONORTHOGONAL rule applies to M4; all edges must be at 0° or 90°. All resize operations alter only axis-aligned edges and thus satisfy this constraint by construction, as confirmed by the accepted repair in trial:i01.cu.def:VIA_VIA34_1_2_58_52.00.
