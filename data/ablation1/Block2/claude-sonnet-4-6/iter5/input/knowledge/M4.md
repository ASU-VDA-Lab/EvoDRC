  def offgrid_cl(axis, pitch_dbu, offset_dbu, base_dbu = nil)
    new_data = RBA::Region::new
    self.data.each do |p|
      bb = p.bbox
      if base_dbu
        if axis == :y
          next if bb.bottom % base_dbu != 0 || bb.top % base_dbu != 0
        else
          next if bb.left % base_dbu != 0 || bb.right % base_dbu != 0
        end
      end
      cl = axis == :y ? (bb.bottom + bb.top) / 2 : (bb.left + bb.right) / 2
      if (cl - offset_dbu) % pitch_dbu != 0
        if axis == :y
          new_data.insert(p.moved(0, cl - bb.bottom))
        else
          new_data.insert(p.moved(cl - bb.left, 0))
        end
      end
    end
    DRC::DRCLayer::new(@engine, new_data)
  end

  def ongrid_ep(gx_dbu, gy_dbu)
    result = RBA::EdgePairs::new
    self.data.each do |poly|
      pts = poly.each_point_hull.to_a
      pts.each_with_index do |pt, idx|
        offgrid_x = (gx_dbu > 1) && (pt.x % gx_dbu != 0)
        offgrid_y = (gy_dbu > 1) && (pt.y % gy_dbu != 0)
        if offgrid_x || offgrid_y
          pp = pts[(idx - 1) % pts.size]
          np = pts[(idx + 1) % pts.size]
          e1 = RBA::Edge::new(pp, pt)
          e2 = RBA::Edge::new(pt, np)
          result.insert(RBA::EdgePair::new(e1, e2))
        end
      end
    end
    DRC::DRCLayer::new(@engine, result)
  end

## Width Constraints

M4 vertical width is bounded below at 24 nm (M4.W.1) and above at 480 nm (M4.W.2). M4.W.3 prohibits vertical widths that are exact multiples of the 24 nm minimum: 48, 96, 144, 192, 240, 288, 336, 384, 432, and 480 nm are all disallowed. M4.W.4 additionally prohibits 72, 168, 264, 360, and 456 nm. The minimum horizontal width is 44 nm (M4.W.5). No trial in the measured history directly repaired a width violation on M4.

## Track Alignment (M4.AUX.1, M4.AUX.2)

M4.AUX.1 requires all horizontal M4 edges to lie on a 24 nm vertical grid. M4.AUX.2 requires minimum-width M4 track centerlines to satisfy (centerline - 48 dbu) mod 192 dbu = 0. Y-direction instance moves of +/-24 dbu and +/-72 dbu were applied and accepted without AUX.1 violations in trial:i03.ug.leaf_0002.01 (eight instances moved across +/-24 and +/-72 dbu steps); moves of +/-24 dbu across three instances were likewise accepted in trial:i04.ug.leaf_0003.02. These step sizes are integer multiples of the 24 nm grid and are consistent with AUX.1 compliance.

## No-Bend Constraint (M4.AUX.3, M4.AUX.4)

M4.AUX.3 fires on any M4 polygon containing a bend, identified by corners with interior angle in the 0-90deg range. M4.AUX.4 prohibits the horizontal outside edge of a wide M4 polygon from coinciding with a minimum-width routing track edge. X-axis endpoint resizes of M4 polygons p957 (+172 dbu, low end) and p937 (+64 dbu low end, +320 dbu high end) were applied in trial:i02.ug.leaf_0001.00 and trial:i03.ug.leaf_0002.01 respectively, and both were accepted without producing AUX.3 or AUX.4 violations.

## Spacing Rules (M4.S.1-M4.S.5)

M4.S.1 enforces a minimum 24 nm vertical projection spacing between M4 polygons and a 1 nm absolute minimum. M4.S.2 enforces 40 nm minimum horizontal spacing between vertical edges. M4.S.3 and M4.S.4 each require 40 nm minimum tip-to-tip spacing between M4 polygons on adjacent tracks (non-parallel-run-length and parallel-run-length cases respectively). M4.S.5 requires a minimum 44 nm parallel run length for adjacent M4 track pairs. No spacing violation was directly repaired in the measured history.
